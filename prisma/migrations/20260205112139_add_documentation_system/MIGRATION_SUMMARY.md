# Documentation System Migration Summary

## Migration Details

**Migration ID:** `20260205112139_add_documentation_system`  
**Created:** 2026-02-05  
**Status:** Ready to apply  
**Type:** Schema addition (new tables only)

## What This Migration Does

This migration creates the complete database schema for the dual documentation system, which provides:

1. **Tenant Documentation Portal** (`/docs`) - Public documentation for PricePilot users
2. **Admin Documentation Portal** (`/admin-docs`) - Restricted documentation for system administrators

## Tables Created (7 total)

### 1. DocumentationDocument
**Purpose:** Stores all documentation content  
**Key Features:**
- Separate TENANT and ADMIN documentation types
- Unique slugs per type for URL routing
- Stores both Markdown (content) and HTML (htmlContent)
- Flexible metadata field (JSON) for tags, author, description, etc.
- Category-based organization

**Indexes:**
- `(type, slug)` - UNIQUE - Fast document lookups
- `(type, category)` - Category browsing
- `slug` - Redirect handling
- `updatedAt DESC` - Recent changes

### 2. DocumentationVersion
**Purpose:** Version history for all documentation changes  
**Key Features:**
- Stores previous content before updates
- Records who made changes and when
- Supports change descriptions
- Enables revert functionality

**Indexes:**
- `(documentId, createdAt DESC)` - Version history queries

### 3. DocumentationSuggestion
**Purpose:** Automated documentation update suggestions  
**Key Features:**
- Generated by documentation hook when tasks complete
- Links to existing docs or suggests new ones
- Approval workflow (PENDING → APPROVED/REJECTED)
- Tracks which task triggered the suggestion

**Indexes:**
- `(status, createdAt DESC)` - Pending review queue
- `documentId` - Suggestions per document

### 4. DocumentationPageView
**Purpose:** Analytics for page views  
**Key Features:**
- Tracks document views with timestamps
- Records user IDs (if authenticated) and session IDs
- Measures time spent on page
- Separates tenant vs admin portal analytics

**Indexes:**
- `(documentId, viewedAt DESC)` - Per-document analytics
- `(type, viewedAt DESC)` - Portal-wide analytics

### 5. DocumentationSearch
**Purpose:** Search query analytics  
**Key Features:**
- Logs all search queries
- Tracks result counts
- Records clicked results for relevance tuning
- Separates tenant vs admin searches

**Indexes:**
- `(type, searchedAt DESC)` - Search analytics
- `query` - Popular search terms

### 6. DocumentationFeedback
**Purpose:** User feedback on documentation quality  
**Key Features:**
- 1-5 star ratings
- Optional comments
- Links to user (if authenticated)
- Helps identify documentation gaps

**Indexes:**
- `(documentId, createdAt DESC)` - Per-document feedback
- `rating` - Low-rated content identification

### 7. DocumentationRedirect
**Purpose:** URL redirects for migrated documentation  
**Key Features:**
- Maps old paths to new paths
- Supports documentation reorganization
- Prevents broken links after migration

**Indexes:**
- `oldPath` - UNIQUE - Fast redirect lookups

## Enums Created (2 total)

### DocumentationType
- `TENANT` - Documentation for regular users
- `ADMIN` - Documentation for administrators

### DocumentationSuggestionStatus
- `PENDING` - Awaiting review
- `APPROVED` - Accepted and published
- `REJECTED` - Declined

## Multi-Tenancy Design Decision

**Important:** Documentation tables do NOT include `tenantId` columns because:

1. Documentation is **system-wide**, not tenant-specific
2. Tenant docs are **publicly accessible** to all users
3. Admin docs are **role-restricted**, not tenant-restricted
4. Documentation describes the PricePilot system itself, not tenant data

This differs from other tables in the system (products, sites, etc.) which are tenant-isolated.

## Performance Optimizations

### Indexes
- All foreign keys automatically indexed
- Composite indexes for common query patterns
- DESC indexes on timestamps for recent-first queries
- Unique constraints prevent duplicate slugs per type

### Full-Text Search Support
Additional indexes can be added via `add_fulltext_search_indexes.sql`:
- GIN index on `to_tsvector(title || content)` for fast full-text search
- Trigram indexes for fuzzy matching and typo tolerance
- Requires `pg_trgm` extension

### Expected Query Patterns
1. Document retrieval: `WHERE type = ? AND slug = ?`
2. Category browsing: `WHERE type = ? AND category = ?`
3. Version history: `WHERE documentId = ? ORDER BY createdAt DESC`
4. Analytics: Time-range queries on viewedAt/searchedAt
5. Feedback aggregation: `WHERE documentId = ?`
